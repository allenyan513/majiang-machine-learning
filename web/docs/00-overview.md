# 第 0 章 全景：你要造的东西

## 这份教程是什么

一个能打麻将的 AI，从零开始，一行行写出来。不调用任何现成的麻将库，不用 RL 框架（stable-baselines / RLlib 都不用），PPO 自己写。全部代码加起来不到 3000 行，跑在一台笔记本上。

读者假设：会 Python，知道什么是类和递归，见过 numpy，**不需要**懂麻将，**不需要**学过强化学习。神经网络部分假设你知道"有个东西叫梯度下降"，其余从头讲。

学完你会得到两样东西。一是一个能和你对打的麻将 AI，二是——更重要的——一套"把一个游戏变成机器学习问题"的完整流程：怎么设计状态表示，怎么造第一个基线，怎么判断模型到底变强了还是只是运气好。这套流程换成别的棋牌游戏（斗地主、桥牌、德州）几乎可以照搬。

## 为什么是麻将

因为麻将难在有意思的地方。

围棋和象棋是**完美信息**博弈：棋盘上的一切你都看得见，理论上可以往下搜索。麻将不是——对手手里 13 张牌你一张都看不到，牌墙里剩什么你也不知道。这类问题叫**不完美信息博弈**，它的难点不是"算得深"，而是"在看不全的情况下怎么下注"。

麻将还有几个让它比德州扑克更难的地方：

| 维度 | 麻将 | 对比 |
|---|---|---|
| 隐藏信息量 | 3 家 × 13 张手牌 + 70 张牌墙 | 德州每人 2 张底牌 |
| 一局决策数 | 每人 15–20 次打牌 | 德州每人 4 个街的下注 |
| 奖励稀疏度 | 打 60 张牌，最后才知道胡没胡 | 类似 |
| 玩家数 | 4 人，别人碰你的牌会打乱顺序 | 2 人零和有完整理论 |

微软的 Suphx（2020）是第一个在天凤上打到十段的麻将 AI，用了 4 块 GPU 训了几个月。我们显然做不到那个水平——但整个技术栈（监督学习热启动 → 自对局强化学习 → 策略蒸馏）是一样的，规模缩小 1000 倍后仍然能跑通，而且每一步你都看得懂。

## 规则：简化推倒胡

真麻将的规则（番型、花牌、门清、杠上开花……）多到能写一本书。我们砍到只剩骨架：

- **牌**：万、条、筒各 1–9，字牌东南西北中发白，每种 4 张，共 136 张
- **胡牌**：4 个面子（3 张顺子或刻子）+ 1 个对子，或者七对
- **动作**：摸、打、碰、杠、胡。**没有吃**（吃会让顺序判定复杂一倍，收益不大）
- **计分**：点炮 1 分，自摸每家 1 分。**没有番型**

为什么把计分砍这么狠？因为我们要让 AI 先学会"胡牌比不胡好、自摸比点炮好"这个最基本的信号。番型是一层乘法因子，会让奖励方差爆炸，早期只会干扰学习。规则常量全部集中在一个 8 行的文件里（`majiang/engine/rules.py`），以后想加回来只改那里。

**这是工程决策，不是偷懒**：先让整条流水线在最简单的规则上跑通，再逐步加复杂度。反过来做（先实现完整规则再训练）你会在第三周还在 debug 番型判定，一次训练都没跑过。

不过这个决定有一个当时没看到的代价，第 13 章会讲：点炮只扣 1 分，让"防守"在这套规则里几乎不值钱——这既限制了规则 bot，也限制了强化学习能学到的东西。

## 六个阶段

项目按阶段推进，每个阶段结束都有一个**能跑的东西**，而不是"写完全部才能测"。前四个阶段是教程的主线（第 1–11 章），后两个是撞墙之后的探索（第 13–14 章）。

```
阶段 1  引擎        136 张牌的状态机 + 胡牌判定 + 向听数
          ↓ 产出：4 个随机 bot 能打完一局，测试验证牌数守恒
阶段 2  规则 bot     牌效率 + 简单防守
          ↓ 产出：对 3 个随机 bot 胜率 84%；四家都是规则 bot 时流局率降到 0
阶段 3  监督学习     规则 bot 自对局 → 神经网络模仿它
          ↓ 产出：86.8% 一致率，实战打平老师
阶段 4  强化学习     PPO 自对局微调，目标是超过老师
          ↓ 产出：一个诚实的负面结果，和知道为什么
阶段 5  改进老师     校准式防守模块，让规则 bot 学会"什么时候该收"
          ↓ 产出：模型准确但分数不涨——发现是规则本身让防守不值钱
阶段 6  换规则？     试着转向日本立直麻将，引擎做完了（majiang/riichi/）
          ↓ 结论：规则复杂度和教程理念冲突，主线退回简化规则。第 14 章记录了这次尝试
```

这个顺序不是随便排的，它回答了一个关键问题：**为什么不直接上强化学习？**

答案是从零开始的 RL 在麻将上根本不收敛。想象一个什么都不会的 AI：它随机打牌，一局打 60 张，最后流局，奖励 0。再来一局，还是流局。要靠随机探索碰巧摸到"4 面子 + 1 对子"的概率低到可以忽略——奖励信号几乎全是 0，梯度里全是噪声。

围棋能从零开始（AlphaZero）是因为每局必分胜负，奖励永远是 ±1。麻将的流局、以及"胡牌需要一长串正确决策的配合"，让随机探索这条路走不通。所以我们**先用规则 bot 造一个会打牌的老师，用监督学习把它的知识灌进网络，再用 RL 在这个起点上微调**。这就是 Suphx 和 AlphaGo（初代，不是 Zero）都用的路线。

## 阶段 4 的结果：诚实地说，没成

先剧透：第一次 PPO 训练**没有超过老师**。60 轮训练、6 万局自对局，最后配对评估显示 RL 模型比规则 bot 差 0.021 分（95% 置信区间 ±0.042，也就是说统计上分不清谁强）。

这份教程会花一整章（第 10 章）讲为什么，以及怎么从训练曲线上读出失败原因。因为在真实的机器学习项目里，第一次跑不出结果才是常态，而**能从失败里读出信息**比运气好跑出正数更有价值。

如果你只想看"哇 AI 变强了"的故事，网上教程很多。这份教程给你的是：一条完整的、可复现的、包括失败在内的真实路径。

## 环境准备

```bash
git clone https://github.com/allenyan513/majiang-machine-learning
cd majiang-machine-learning
uv sync          # 装依赖（numpy + torch，开发组多装 pytest 和 matplotlib）
uv run pytest -q # 43 个测试应该全过
```

用的是 [uv](https://github.com/astral-sh/uv)，比 pip 快一个数量级，也管 Python 版本（项目锁 3.11）。不想用 uv 就普通 venv + `pip install numpy torch pytest matplotlib`，代码没有任何 uv 特有的东西。

硬件要求：**一台普通笔记本就够**。阶段 3 训练在 MacBook 的 MPS 上 30 秒，阶段 4 的 PPO 60 轮 15 分钟（吃 CPU，因为瓶颈是自对局模拟不是反向传播）。没有 GPU 也能跑，只是慢 2–3 倍。

## 怎么读这份教程

每章结构固定：**原理 → 实现 → 坑 → 验证 → 练习**。

原理部分讲"为什么这么做"，实现部分贴真实代码（不是伪代码，都是仓库里能跑的），坑是我们实际踩过的，验证告诉你怎么确认自己写对了，练习没有标准答案。

建议的读法：**边读边自己写一遍**。把仓库当答案，每章先自己实现，卡住了再看。特别是第 2、3 章（胡牌判定和向听数），自己写一遍的收获远大于读十遍。

第 8 章（强化学习原理）是唯一一章可以先跳过的——如果你已经懂 PPO，直接去第 9 章看怎么接到麻将上。
