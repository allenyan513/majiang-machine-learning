# 第 15 章 改一行计分，重跑整条流水线

> 对应代码：`majiang/engine/rules.py`（`RON_POINTS = 3`）。本章所有数字都是在这个计分下重新测的；第 5–13 章的数字是 `RON_POINTS = 1` 时的。

第 13 章的结论是"点炮只扣 1 分，防守不值钱"。第 14 章去研究了日本立直麻将，引擎都做出来了，最后发现规则复杂度和这份教程的目的冲突，退了回来。但日麻带回来一个便宜的东西：**它的计分结构**——点炮全赔、自摸分摊。这个结构不需要役种和番符，一行常量就能搬进简化规则：

```python
RON_POINTS = 3          # 点炮：放炮者付给胡家（原来 1）
TSUMO_POINTS_EACH = 1   # 自摸：其他三家各付 1（不变）
```

现在一次放炮 = 三次被自摸分摊。"别放炮"第一次有了分量。这一章把第 2–4 章的流水线在新计分下从头跑一遍，看每一步的结论变没变。

## 结果对照

| 环节 | 旧计分（点炮 −1） | 新计分（点炮 −3） |
|---|---|---|
| 规则 bot vs 3 随机（500 局） | 胜率 84.2%，均分 +1.25 | 胜率 82.0%，均分 +2.45 |
| 4 规则 bot 自对局 | 流局 0%，放炮 18.7% | 流局 1.0%，放炮 16.9% |
| 防守 v2 vs v1（6000 局配对） | −0.007 ± 0.013（无用） | **+0.045 ± 0.040（有用）** |
| 监督模型一致率（1 万局数据） | 86.8% | 84.3% |
| 监督模型 vs 老师（配对） | −0.015 ± 0.042（打平） | **−0.101 ± 0.062（落后）** |
| 监督模型一致率（3 万局数据） | — | 86.9% |
| 监督模型 vs 老师（3 万局） | — | −0.048 ± 0.058（回到噪声内） |
| PPO 60 轮 vs 老师 | −0.021 ± 0.042 | −0.119 ± 0.063（无改善） |
| 单局分数标准差 | 1.0 | 1.6 |

四个结论，一个一个说。

## 1. 防守值钱了，但没有想象中值钱

第 13 章那个校准准确却毫无收益的危险度模型，在新计分下终于有了正收益：对手是 v2 时 +0.045 ± 0.040，放炮率 20.9% → 18.7%。方向对了，显著性刚过线。

为什么只有这么多？因为规则 bot 的**进攻逻辑没变**——它仍然是"向听数优先"，防守只在同向听的候选牌之间挑一张更安全的。真正的防守（放弃进攻、全力弃听）要打破向听优先，而第 13 章的坑 1 说明价值表还撑不起这种跨向听的决策。计分让防守有了价值，但要兑现这个价值，老师本身还得再进化。

## 2. 学生跟不上老师了——然后靠数据追回来

这是新计分下最意外的一条。旧计分时监督模型和老师打平，新计分下同样的 1 万局数据训出来的模型**明显落后**（−0.10）。

两个原因叠加：
- **老师变难模仿了。** v2 的一部分决策来自危险度 × 价值表的期望值比较，不像 v1 的"向听 > 进张"那样有清晰的规律。一致率从 86.8% 掉到 84.3%。
- **错误的代价变大了。** 学生放炮率 20.4%、老师 18.9%——这 1.5 个点在旧计分下值 −0.015，在新计分下值 −0.045，再加上少胡的牌，就是 −0.1。

把数据从 1 万局加到 3 万局：一致率 84.3% → 86.9%，差距 −0.101 → −0.048。**数据翻三倍，差距减半，回到了噪声范围内。** 说明落后主要是数据不够，不是特征缺信息——如果特征里没有防守需要的信息（对手牌河、副露、可见张数），加多少数据都补不回来。第 6 章设计特征时把这些都放进去了，这里是它的回报。

顺带一个教训：第 7 章说"一致率和实战强度没有单调关系"，这里补一句——**在一致率还不够高的区间，它们是有关系的**。84% → 87% 对应了实打实的 +0.05。那句警告针对的是"已经很高了还去抠最后几个点"的情况。

## 3. RL 还是没超过老师，而且现在更难看清

60 轮 PPO 之后配对评估 −0.119 ± 0.063，和监督模型（−0.101）没有区别。训练曲线上，400 局的贪心评估在 −0.18 到 +0.04 之间乱跳，看不出任何趋势；价值损失 2.2 全程不降。

比旧计分时更糟的是**噪声**。单局分数的标准差从 1.0 涨到 1.6，所有置信区间宽了 60%。第 10 章那张"要多少局才能分辨多大差距"的表，局数要全部乘 2.5。RL 每 5 轮做一次 400 局评估，在旧计分下标准误是 0.05，现在是 0.08——曲线上 ±0.1 的起伏全是噪声。

这是计分放大的直接代价：**信号变清楚了，噪声也变大了**。要在新计分下把 RL 做出结论，评估局数至少要 2000 起，或者换成第 12 章说的先知教练来压方差。

## 4. 一行改动的连锁反应

改一个常量，整条流水线的数字全变了，两个之前成立的结论翻了（防守有用了、学生跟不上了），一个之前的结论保持（RL 没超过老师）。这就是为什么第 5 章要花那么大篇幅讲评估框架——**没有配对评估和置信区间，这一章的每一行都可能是错的**。

也是为什么教程的数字要标明测量条件。第 5–13 章的数字全部是 `RON_POINTS = 1` 时测的，想复现就把常量改回去；本章是 `= 3`。以后再改规则，这张对照表往下加一列。

## 现在的默认配置

从这一章起，仓库的默认是：`RON_POINTS = 3`，规则 bot 默认 `defense="v2"`，监督数据 3 万局，`models/discard.pt` 是 3 万局训出来的模型。README 里的命令已经对应更新。
