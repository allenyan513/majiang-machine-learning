# 第 13 章 改进老师：规则决定了上限

> 对应代码：`majiang/agents/defense.py`、`majiang/agents/defense_tables.py`、`majiang/ml/calibrate_defense.py`、`majiang/agents/rule_agent.py`（`defense="v2"`）

> **计分说明**：本章的数字是在初版计分 `RON_POINTS = 1`（点炮扣 1 分）下测得的。仓库现在默认 `RON_POINTS = 3`，同样的命令跑出来数字会不同——对照表和原因见[第 15 章](15-rescoring.md)。要复现本章，把 `majiang/engine/rules.py` 里的常量改回 1。

第 12 章把"改进老师"列为最推荐的路线：规则 bot 的防守只有一条弱启发式，补上真正的防守，老师变强，整条流水线的终点跟着抬高。这一章记录我们真的走了一遍之后发生了什么。

剧透：防守模块本身做对了，**但规则 bot 没有变强**。原因不在算法，在第 0 章那个"把计分砍到最简"的决定。这一章是整份教程里最能说明"规则设计决定学习上限"的一章。

## 原理：防守是一个期望值问题

第 5 章的防守逻辑是"对手副露 ≥ 3 组时，他打过的牌算安全"。它的问题不是判断准不准，而是**没有量**：它不知道对手听牌的概率是 30% 还是 90%，也不知道打出某张牌被胡的概率是 0.1% 还是 10%。没有量，就没法和进攻的收益做权衡，只能用 if-else 拍板。

真正的防守要回答两个概率问题：

1. **威胁**：每个对手现在听牌的概率有多大？
2. **危险度**：如果他听了，我打出的这张牌在他的听牌集合里的概率有多大？

两者相乘，就是"这张牌打出去被胡的概率"。有了它，打牌决策可以写成期望值：

```
EV(打 d) = (1 − 危险度(d)) × V(打完 d 之后的状态) − 危险度(d) × 放炮损失
```

`V` 是"处于某个状态时，这局最终平均能得几分"——就是第 8 章讲的价值函数，只不过这里不用神经网络，用一张查表。

这两个概率和这张价值表从哪来？**从规则 bot 自己的对局里统计**。这是上帝视角能做到的事：模拟时我们看得到所有人的手牌，可以直接数"副露 2 组、打了 8 张牌的人里，有多少比例已经听牌"。这个思路叫**策略评估**（policy evaluation）：先评估当前策略的表现，再用评估结果改进策略——它和第 8 章的 Actor-Critic 是同一个思想的两个实现。

## 实现

### 校准：三张表

`ml/calibrate_defense.py` 跑几千局规则自对局，每次有人要打牌时，从上帝视角记三件事：

**表 1：P(听牌 | 副露数, 已打张数)**

| 副露数 \ 已打张数 | 0–3 | 4–7 | 8–11 | 12–15 | 16+ |
|---|---|---|---|---|---|
| 0 | 0.00 | 0.07 | 0.23 | 0.42 | 0.56 |
| 1 | 0.04 | 0.17 | 0.37 | 0.50 | 0.66 |
| 2 | 0.27 | 0.43 | 0.58 | 0.72 | 0.79 |
| 3 | — | 0.67 | 0.83 | 0.75 | 0.97 |

读法：一个碰了两次、打了 10 张牌的对手，有 58% 的概率已经听牌。第 5 章那条"副露 ≥ 3 才算威胁"的规则，在这张表里对应的是最右下角——它漏掉了左边大片 40%–70% 的区域。

**表 2：P(在听牌集合里 | 已听牌, 牌的类别, 可见张数, 他是否打过)**

| 类别 \ 可见张数 | 0 | 1 | 2 | 3 | 他打过 |
|---|---|---|---|---|---|
| 字牌 | 0.026 | 0.003 | 0.002 | 0.000 | ≈0 |
| 幺九 | 0.055 | 0.033 | 0.029 | 0.021 | ≈0.005 |
| 二八 | 0.088 | 0.066 | 0.047 | 0.030 | ≈0.002 |
| 中张 | 0.099 | 0.089 | 0.077 | 0.054 | ≈0.003 |

这张表把麻将防守的常识全部量化了：中张最危险、字牌最安全、见得越多越安全、**对手打过的牌几乎绝对安全**（不是因为振听——推倒胡没有振听——而是因为规则 bot 不会拆掉一个搭子再去听它）。

**表 3：V(向听数, 进张数, 牌墙剩余, 最大威胁)**

打完某张牌后处于该状态时的平均终局分数。摘一部分（对牌墙和威胁取平均）：

| 打后向听 \ 进张 | 0 | 1 | 2 | 4 | 8 | 12 | 20 | 30+ |
|---|---|---|---|---|---|---|---|---|
| 0（听牌） | −0.15 | +0.01 | +0.06 | +0.34 | +0.74 | | | |
| 1 | | −0.55 | −0.24 | −0.34 | −0.16 | +0.06 | +0.11 | +0.35 |
| 2 | | | | | −0.30 | −0.19 | −0.08 | 0.00 |
| 3 | | | | | | −0.40 | −0.21 | −0.10 |

有意思的读法：**听牌但只有 0 张进张（听的牌全没了）比 1 向听 20 进张还差**。这是第 3 章"向听数第一、进张数第二"那个排序 key 抓不到的——它把"向听"当成严格优先级，永远不会为了进张放弃向听。

样本少的格子（少于 30 次）逐级回退到边际均值，否则表里全是噪声。

### 用表决策

```python
def _discard_v2(self, obs, options, best_shanten):
    threat = defense.max_threat(obs)
    danger = defense.danger_map(obs)

    def key(opt):
        d, s, n = opt
        v = defense.value(s, n, obs.wall_remaining, threat)
        ev = (1 - danger[d]) * v - danger[d] * self.DEAL_IN_COST
        iso = 2 if is_honor(d) else 1 if is_terminal(d) else 0
        return (-s, round(ev, 4), n, iso)   # 向听优先；同向听内比 EV

    return Action(ActionType.DISCARD, max(options, key=key)[0])
```

旧逻辑保留为 `defense="v1"`，评估时两个版本可以直接对打。

## 坑

### 坑 1：跨向听比 EV 会崩

第一版的 key 是纯 EV，不管向听数。结果对 v1 的配对评估 **−0.124 ± 0.028**，大崩。

原因是表 3 有采样偏差：状态"1 向听、20 进张"的 V 是 +0.11，但这些样本几乎全部来自开局（牌多、时间多）。中盘一个"听牌、4 进张"（V = +0.34）的手，按表算竟然不如退回 1 向听——因为表里的 1 向听样本是开局的好局面。价值表描述的是"规则 bot 会在什么时候处于这个状态"，不是"任何时候处于这个状态的价值"。

这是策略评估的经典陷阱：**价值表是在当前策略的状态分布上估的，用它评估当前策略不会到达的状态就是外推**。第 8 章的 critic 有同样的问题，只是被神经网络的泛化掩盖了。

修法：向听数保持严格优先，EV 只在同向听内比较。这样表 3 只用来做"同向听下进张 vs 危险"的权衡，不再跨分布外推。

### 坑 2：分桶让 EV 退化成"只看危险度"

表 3 的进张数是分桶的（0, 1, 2, 3, 4, 6, 8, 12, 20, 30）。桶内 V 相同，EV 的差异就只剩危险度那一项——bot 会为了 0.1% 的安全，放弃一桶之内的好几张进张。加了桶间线性插值才修掉。

### 坑 3：多进程 + 从 stdin 跑脚本

排查座位偏差时，用 `python - <<EOF` 跑一个带 `multiprocessing.Pool` 的脚本，卡死 10 分钟。macOS 的子进程启动方式是 spawn，要重新导入主模块，而 stdin 里的脚本没有可导入的文件。写成 `.py` 文件再跑就好。

## 验证

### 危险度模型是准的

1500 局、6 万次打牌决策，按预测危险度分桶看实际放炮率：

| 预测危险度 | 决策占比 | 实际放炮率 | 占全部放炮 |
|---|---|---|---|
| < 0.5% | 52% | 0.08% | 2% |
| 0.5%–1% | 9% | 0.47% | 2% |
| 1%–2% | 15% | 1.5% | 12% |
| 2%–4% | 13% | 2.8% | 20% |
| 4%–8% | 9% | 7.2% | 38% |
| ≥ 8% | 3% | 14.0% | 25% |

区分力很强：最危险的 3% 决策贡献了 25% 的放炮，最安全的 52% 只贡献 2%。预测值和实际值也对得上（预测 4%–8% 的桶实际放炮 7.2%），说明校准没有系统偏差。**模型是对的。**

### 但分数没涨

6000 局配对评估（`compare.py --opponent` 让两个方向都测）：

| 版本 | 思路 | vs v1（对手 = v1） | vs v1（对手 = v2） |
|---|---|---|---|
| 分档策略 | 威胁高时弃听/挑安全牌 | −0.007 ± 0.013 | −0.007 ± 0.013 |
| 纯 EV | 跨向听比期望值 | **−0.124 ± 0.028** | **−0.198 ± 0.033** |
| 向听优先 + 同向听 EV | 修坑 1 | −0.029 ± 0.023 | −0.022 ± 0.025 |
| + 插值 + 8000 局校准 | 修坑 2 | −0.019 ± 0.019 | −0.025 ± 0.021 |

放炮率确实降了（19.0% → 18.5%），但胜率也降了（24.5% → 23.4%），净效果是零或者微负。**一个准确的危险度模型，用进决策后不产生收益。**

## 为什么：算一笔账

回到 `rules.py`：

```python
RON_POINTS = 1          # 点炮：放炮者付给胡家
TSUMO_POINTS_EACH = 1   # 自摸：其他三家各付给胡家
```

防守能避免的损失是 **1 分**。规则 bot 每局放炮率 19%，就算防守做到完美、把放炮降到 0 而且不付任何代价，上限也只有 +0.19。但代价不可能是零：每次为了安全打掉一张进张，都在降低自己胡牌的概率，而胡一次是 +1 到 +3。

换句话说，在这套计分下，**"永远进攻"几乎就是最优策略**。防守模块再准，也只能在极少数"安全牌和进张牌恰好是同一张"的局面里起作用——那正是 v1 那条弱启发式已经覆盖的局面。

对比真实麻将的计分：日本立直麻将里点炮者付全额，一次放炮满贯是 8000 点，而一次普通胡牌只有 1000–3000 点——**放一炮亏掉两三次胡牌**。防守不是可选项，是核心技术。中国国标里点炮者付 8 + 番数、其他两家各付 8，同样是放炮者承担大头。

第 0 章说"计分砍到最简是工程决策，不是偷懒，先让流水线跑通"。这个决定在阶段 1–3 是对的。但它有一个当时没意识到的后果：**它把游戏变成了一个防守不值钱的游戏**。阶段 4 的 RL 学不到超过老师的东西，阶段 5 的防守模块不产生收益，根子是同一个——在这套规则下，"超过向听数贪心"这件事本身没有多少空间。

## 这一章的结论

三条，按重要性排：

1. **规则设计决定学习的上限。** 一个 AI 能学到的东西，不会超过奖励函数里存在的东西。如果计分让防守不值钱，再好的防守模块也没用，再多的 RL 也学不出防守。做任何游戏 AI 之前，先问：这套规则下，我希望它学会的技能真的有分数吗？

2. **策略评估的表只在当前策略的状态分布上有效。** 拿它跨分布比较（坑 1）会给出自信的错误答案。神经网络的 critic 有同样的问题，只是更隐蔽。

3. **一个准确的模型和一个有用的模型是两回事。** 危险度模型的区分力很强（验证一节），但在决策里没有收益。验证一个模型，不能只看它预测得准不准，要看用它做决策后目标指标变没变。

下一步不是继续调防守，而是**换一套让防守有分量的规则**。第 14 章研究业界标准的日本立直麻将——它也是 Suphx、Mortal 这些麻将 AI 用的规则，有公开的人类牌谱和开源对手可以做标尺。
