# 第 8 章 强化学习原理：从策略梯度到 PPO

> 这一章没有项目代码，只有原理。已经懂 PPO 的可以直接跳到[第 9 章](09-ppo.md)。

## 问题的形状：MDP

强化学习研究的是这样一类问题：一个**智能体**在**环境**里反复做决策，每次决策后环境变化并给一点**奖励**，目标是让长期奖励总和最大。

形式化成**马尔可夫决策过程**（MDP）：

| 符号 | 名字 | 麻将里是什么 |
|---|---|---|
| s | 状态 | 当前局面（我们的 `Observation`） |
| a | 动作 | 打哪张牌（34 选 1，掩码后约 10 选 1） |
| r | 奖励 | 终局分数（+3 自摸 / +1 点炮胡 / -1 放炮 / 0 流局） |
| π(a\|s) | 策略 | 神经网络：给定局面输出每张牌的概率 |
| γ | 折扣因子 | 我们用 1.0，因为一局有限长且只关心终局 |

要最大化的是**期望回报**：

```
J(π) = E[ r₁ + γr₂ + γ²r₃ + ... ]
```

麻将不完全满足 MDP 的定义——因为我们看不到完整状态（别人的手牌），严格说是 **POMDP**（部分可观测 MDP）。实践中的处理是"把观察当状态用"，配合能记住历史的特征（牌河就是历史的摘要）。这在理论上不完美，在工程上通行。

## 为什么不用 Q-learning

RL 有两大流派。**基于价值**的（Q-learning、DQN）学一个函数 Q(s,a) 估计"在状态 s 做动作 a 最终能得多少分"，然后每步选 Q 最大的动作。**基于策略**的（策略梯度、PPO）直接学策略 π(a|s)，输出动作概率。

我们选策略梯度，三个理由：

1. **起点是监督学习的策略网络。** 阶段 3 训出来的东西就是一个 π(a|s)，直接拿来当 RL 的初始策略。用 DQN 的话要先把策略转成 Q 函数，很别扭
2. **随机策略在不完美信息博弈里是必需的。** 麻将里对手会观察你的打法，确定性策略会被针对（这是博弈论的结论：不完美信息博弈的纳什均衡通常是混合策略）
3. **动作空间随局面变化。** 每次能打的牌不同，Q-learning 的 argmax 要配合掩码，比策略梯度的掩码 softmax 麻烦

## 策略梯度：核心公式

我们要对 J(π) 求梯度然后上升。问题是 J 是一个期望，里面套着环境的随机性（摸什么牌、对手怎么打），没法直接求导。

**策略梯度定理**给出了答案：

```
∇J(θ) = E[ ∇log π(a|s) · G ]
```

其中 G 是这一步之后拿到的总回报。

**怎么直观理解？** `∇log π(a|s)` 是"让动作 a 概率变大的方向"。乘上 G 之后：

- 如果这个动作最终导致高回报（G 大），就沿这个方向走一大步 → 以后更可能这么做
- 如果导致低回报（G 为负），就往反方向走 → 以后更少这么做

**试错学习的数学化**。这条公式的美妙之处是它只需要采样：打几局，记下每步的动作和最终得分，就能估计梯度。不需要知道环境的转移概率。

### 减方差：基线和优势

原始公式方差极大。假设麻将的所有回报都在 +1 到 +3 之间（都是正的），那么每个动作的概率都在被推高——只是推的力度不同。这在数学上是对的（softmax 会归一化），但采样噪声会淹没信号。

解法是减掉一个**基线** b(s)，通常取状态价值 V(s) = "从这个状态出发平均能得多少分"：

```
A(s,a) = G - V(s)      优势函数（advantage）
∇J(θ) = E[ ∇log π(a|s) · A(s,a) ]
```

现在的含义变成了：**这个动作比平均水平好多少**。比平均好就加强，比平均差就削弱。可以证明减基线不改变梯度的期望（因为 E[∇log π · b(s)] = 0），只降低方差。

估计 V(s) 需要第二个网络（或共享主干的第二个头），这就是 **Actor-Critic** 架构：

- **Actor**（演员）= 策略网络 π，决定做什么
- **Critic**（评论家）= 价值网络 V，评价局面好坏

我们的 `ActorCritic` 类就是共享卷积主干、两个头。

### GAE：在偏差和方差之间调旋钮

优势可以有很多种估计方式：

```
A = r + γV(s') - V(s)                        单步 TD：方差小，但依赖 V 准确（偏差大）
A = r₁ + γr₂ + ... + γⁿrₙ - V(s)             蒙特卡洛：无偏，但方差极大
```

**GAE**（Generalized Advantage Estimation）用一个参数 λ 在两者间插值：

```
δₜ = rₜ + γV(sₜ₊₁) - V(sₜ)                   单步 TD 误差
Aₜ = δₜ + (γλ)δₜ₊₁ + (γλ)²δₜ₊₂ + ...        指数加权和
```

λ=0 退化成单步 TD，λ=1 退化成蒙特卡洛。常用 0.95，我们也用这个值。

实现是一个从后往前的循环：

```python
def gae(r, v, done, gamma, lam):
    adv = np.zeros_like(r)
    last = 0.0
    for t in range(len(r) - 1, -1, -1):
        next_v = 0.0 if done[t] else v[t + 1]
        delta = r[t] + gamma * next_v - v[t]
        last = delta + gamma * lam * (0.0 if done[t] else last)
        adv[t] = last
    return adv, adv + v
```

`done[t]` 处两次截断（`next_v` 和 `last`）是关键：一局结束后，下一局的信息不能往回传。这个 bug 极难发现（训练会继续跑，只是变慢变差），所以我们专门写了测试：

```python
def test_gae_two_episodes_do_not_leak():
    r = np.array([0.0, 1.0, 0.0, -1.0])
    v = np.array([0.0, 0.0, 0.0, 0.0])
    done = np.array([False, True, False, True])
    adv, _ = gae(r, v, done, gamma=1.0, lam=1.0)
    assert np.allclose(adv, [1.0, 1.0, -1.0, -1.0])
```

如果 episode 边界泄露，第二局的 -1 会污染第一局的优势值。

## PPO：为什么需要它

朴素策略梯度有个致命问题：**步子迈大了会崩。**

策略更新一步之后，采样用的旧策略和新策略不一样了，之前采的数据就不能用了（分布变了）。要么每次更新只用一批数据然后扔掉（样本效率极低），要么用重要性采样修正：

```
ratio = π_new(a|s) / π_old(a|s)
L = E[ ratio · A ]
```

但重要性采样在两个分布差太远时方差爆炸——某个 ratio 变成 100，梯度直接把网络打飞。

**TRPO** 的解法是加一个 KL 散度约束，用二阶优化求解，数学优美但实现复杂。**PPO**（Proximal Policy Optimization）用一个粗暴但极其有效的近似：**直接把 ratio 截断**。

```
L = E[ min( ratio · A,  clip(ratio, 1-ε, 1+ε) · A ) ]
```

ε 通常取 0.2。这个公式的行为：

| 情况 | ratio | 效果 |
|---|---|---|
| 好动作（A>0），概率已涨过头 | > 1.2 | clip 生效，梯度归零，不再加强 |
| 好动作，概率还没涨够 | < 1.2 | 正常加强 |
| 坏动作（A<0），概率已降够 | < 0.8 | clip 生效，不再削弱 |
| 坏动作，概率还没降够 | > 0.8 | 正常削弱 |

**一句话：好的动作加强一点点就够了，别贪心。** 取 min 保证了它是真实目标的下界（悲观估计），所以优化它是安全的。

这个简单的修改让同一批数据可以反复用几轮（我们用 3 轮），样本效率提高数倍，而且几乎不会崩。这就是 PPO 成为 RL 默认选择的原因。

### 完整的 PPO 损失

实际用的损失有四项：

```
L = policy_loss - c_ent · entropy + c_vf · value_loss + c_kl · KL(π ‖ π_teacher)
```

1. **策略损失**：上面的 clip 目标
2. **熵奖励**（减去，即鼓励熵大）：防止策略过早收敛成确定性的，保持探索
3. **价值损失**：`(V(s) - 回报)²`，训练 critic
4. **对老师的 KL 惩罚**：这一项是我们加的，不是 PPO 标配——防止微调跑偏，第 9 章细讲

## 麻将特有的三个麻烦

标准 PPO 假设的是单智能体、稠密奖励、固定动作空间。麻将三个都不满足：

**奖励极稀疏。** 60 次决策共享一个终局奖励。哪一步是关键？算法不知道，只能靠大量采样平均出来。这叫**信用分配问题**（credit assignment），是我们最终失败的直接原因。缓解手段是**奖励塑形**，下一章讲。

**多智能体。** 四个人同时学（或者两个学两个固定），环境对每个 agent 来说是非平稳的——你的对手也在变。理论保证全部失效，实践中靠"对手池"或者"固定一部分对手"缓解。我们让 2 个座位是学习者、2 个是规则 bot，就是后者。

**动作空间变化。** 每步能打的牌不同。掩码解决，但掩码用 `-inf` 在计算熵和 KL 时会产生 `0 × -inf = nan`。下一章的坑。
