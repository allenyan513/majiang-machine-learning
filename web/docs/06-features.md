# 第 6 章 特征工程：把牌桌变成张量

> 对应代码：`majiang/ml/features.py`、`majiang/ml/model.py`、`tests/test_features.py`

神经网络吃的是数字矩阵，麻将局面是一堆手牌、牌河、副露。这一章讲怎么转换——以及为什么这一步的设计比选什么网络结构更影响最终效果。

## 原理：特征设计的三个判断

### 判断一：相对视角还是绝对视角

牌河有四条，分别属于四家。喂给网络时可以按绝对编号（玩家 0、1、2、3），也可以按**相对自己的位置**（自己、下家、对家、上家）。

必须用相对视角。理由：麻将的策略只取决于相对关系——"下家在碰条子"和"上家在碰条子"含义完全不同（下家吃你打的牌，上家喂你牌），但"玩家 1 在碰条子"这个说法本身没有意义。用绝对编号的话，网络要为每个座位单独学一遍同样的知识，样本效率降到 1/4。

```python
for rel in range(4):
    p = (me + rel) % 4
    river = np.bincount(obs.rivers[p], minlength=34)[:34]
    out[68 + rel * 34 : 68 + (rel + 1) * 34] = river
```

这个变换叫**视角归一化**，在所有多人游戏的 AI 里都是标配。

有专门的测试锁住它：

```python
def test_relative_perspective():
    g.rivers[1] = [3, 3]  # 玩家1 打过两张 4m
    c0, c2 = encode_compact(g.observe(0)), encode_compact(g.observe(2))
    # 对玩家0 来说玩家1 是下家 (rel=1)；对玩家2 来说是上家 (rel=3)
    assert c0[68 + 34 + 3] == 2 and c2[68 + 3 * 34 + 3] == 2
```

### 判断二：计数还是 one-hot 平面

手里有 3 张五万，可以编码成 `counts[4] = 3`（一个数），也可以编码成 4 个 0/1 平面：`>=1`、`>=2`、`>=3`、`>=4`。

用平面。这是从 AlphaGo 那里学来的做法，原因是**神经网络对"3 和 4 的差别"不敏感，但对"有没有"很敏感**。数值 3 和 4 在网络看来只差 33%，而实际上"3 张（已经是刻子）"和"4 张（可以杠）"是质变。拆成阈值平面之后，每个平面是一个干净的二值特征，卷积核可以直接学"这里有对子"这种模式。

代价是通道数变多（4 倍），但 34 这个维度太小了，多几个通道毫无压力。

### 判断三：存盘格式和训练格式要分开

训练数据有几十万条，如果直接存展开后的浮点平面：

```
200,000 样本 × 22 通道 × 34 = 1.5 亿个 float32 = 600 MB
```

而存紧凑的 uint8 计数：

```
200,000 × 308 字节 = 62 MB，压缩后约 10 MB
```

所以分两步：

```python
encode_compact(obs) -> uint8[308]        # 存盘用，小
expand(batch)       -> float32[B,22,34]  # 训练/推理用，展开成 0/1 平面
```

`expand` 在训练时每个 batch 调一次，是纯 tensor 运算，开销可以忽略。**存紧凑、算时展开**，这个模式在所有数据量大的 ML 项目里都值得用。

## 实现

### 紧凑格式：308 字节

```
[0:34]     自己手牌计数
[34:68]    自己副露里的牌计数（碰=3，杠=4）
[68:204]   四家牌河计数 4×34（相对视角）
[204:306]  另外三家副露计数 3×34
[306]      刚摸到的牌 (0–33)，没有则 255
[307]      牌墙剩余张数
```

全部是 uint8，因为每个值都 ≤ 136。第 306 位用 255 当"没有"的哨兵值（麻将牌 id 只到 33，不会冲突）。

### 展开：22 个平面

```
0–3    手牌 >=1,2,3,4
4      自己副露里有这张牌
5–12   四家牌河 >=1, >=2（每家 2 个平面）
13–15  三家副露里有这张牌
16–19  牌池里还没见过的张数 >=1,2,3,4
20     刚摸到的牌
21     牌墙剩余 / 100（整平面同一个值）
```

**平面 16–19 是这里唯一的"人工智慧"**：

```python
unseen = 4 - hand - own_meld - rivers.sum(1) - others_meld.sum(1)
for k in range(4):
    planes[:, 16 + k] = (unseen >= k + 1).float()
```

它算的是"这种牌在看不见的地方还剩几张"（牌墙 + 别人手里）。网络理论上能从手牌、牌河、副露自己减出来，但那需要学一个跨通道的减法——白白浪费容量。**能算出来的东西就直接算给它**。

这条原则的另一面是：不要把"策略"编码进特征。比如我们没有把"向听数"当特征喂进去——那等于直接告诉网络答案，它会退化成一个查表器，学不到向听数以外的东西。

平面 21（牌墙剩余）是个标量，展开成整个平面同一个值。这是卷积网络接收全局标量的标准做法。

### 网络：一维卷积

```python
class DiscardNet(nn.Module):
    def __init__(self, channels: int = 64, blocks: int = 3):
        layers = [nn.Conv1d(NUM_PLANES, channels, 3, padding=1), nn.ReLU()]
        for _ in range(blocks - 1):
            layers += [nn.Conv1d(channels, channels, 3, padding=1), nn.ReLU()]
        self.conv = nn.Sequential(*layers)
        self.head = nn.Sequential(
            nn.Flatten(),
            nn.Linear(channels * 34, 256),
            nn.ReLU(),
            nn.Linear(256, 34),
        )
```

**为什么是卷积而不是全连接？** 因为麻将的关键模式是**局部且平移不变**的：

- 345m 是顺子，456m 也是顺子——同一个模式在不同位置
- 55m 是对子，66m 也是对子

`kernel=3` 恰好覆盖一个顺子的宽度。三层卷积之后感受野是 7，足够看到"一条龙"以外的所有局部牌型。用全连接的话，网络要为每个位置单独学"顺子长什么样"，需要多得多的数据。

**参数量**：卷积部分 2.9 万，全连接头 `64×34 → 256 → 34` 约 56.6 万，合计 59.5 万——头部占了 95%。这个比例不太漂亮（可以用全局池化减小），但在我们的数据规模下够用，而且训练只要 30 秒。

**关于字牌**：卷积会把 27–33（东南西北中发白）当成"相邻"来处理，但它们之间没有顺子关系。这不会导致错误，只是那几个位置的卷积核学到的东西和数牌不同。更讲究的做法是分开处理或者在花色边界补零，收益有限，我们没做。

### 掩码：不能打手里没有的牌

```python
@staticmethod
def mask_logits(logits: torch.Tensor, x: torch.Tensor) -> torch.Tensor:
    """手里没有的牌不能打：平面 0 是 hand>=1。"""
    in_hand = x[:, 0] > 0
    return logits.masked_fill(~in_hand, float("-inf"))
```

网络输出 34 个 logits，但手里通常只有 10 来种牌。把不合法的位置设成 `-inf`，softmax 之后概率为 0。

这比"输出之后过滤"好，因为它在**训练时**也生效：交叉熵损失只在合法动作上归一化，网络不用浪费容量去学"不能打没有的牌"这种废话。

**但 `-inf` 在 RL 里会炸**——第 9 章会讲这个坑（`0 × -inf = nan`），那里改用 `-1e9`。

## 验证：形状 + 语义 + 一致性

```python
def test_shapes_and_unseen_consistency():
    obs = g.observe(0)
    x = encode(obs)
    assert x.shape == (1, NUM_PLANES, 34)
    # 开局时自己 14 张，其他都没见过：unseen>=1 应该对所有牌成立
    assert x[0, 16].sum() == 34
    # 手牌平面：>=1 的张数 = 手牌种类数
    assert x[0, 0].sum() == sum(1 for n in obs.hand if n > 0)
    # 刚摸的牌 one-hot
    assert x[0, 20].sum() == 1 and x[0, 20, obs.last_draw] == 1


def test_expand_batch_matches_single():
    rows = np.stack([encode_compact(g.observe(p)) for p in range(4)])
    batch = expand(rows)
    for p in range(4):
        assert torch.equal(batch[p], encode(g.observe(p))[0])
```

最后那个测试防的是**批处理和单条推理不一致**——一个极其常见、极其难查的 bug。训练时走 batch 路径，推理时走单条路径，如果两者有微小差异（比如某个 reshape 写错），模型在训练集上完美，实战中一塌糊涂。写一个 `batch == single` 的断言，一劳永逸。

## 坑

**特征里泄露了未来信息。** 最经典的失误是把"这局最后谁赢了"之类的信息编进特征。我们的 `Observation` 从设计上杜绝了这个（第 4 章），这是把边界做成数据结构的回报。

**忘了 `.float()`。** `expand` 里所有的布尔比较都要显式转 float，否则 PyTorch 的卷积会报类型错误——好在报错很直白。

**uint8 溢出。** 牌河计数最多 4，牌墙剩余最多 136，都在 uint8 范围内。如果以后加了"累计打了多少张牌"这类特征，要检查是否超过 255。

## 练习

1. 加一个"每家副露的组数"特征（0–4）。这是防守的关键信号，现在网络只能从副露的牌反推
2. 把全连接头换成全局平均池化 + 小 MLP，参数量会从 60 万降到 5 万。重新训练，一致率掉多少？
3. 做一次消融实验：去掉 unseen 平面（16–19）重新训练。一致率变化多少？这告诉你这组特征的实际价值
